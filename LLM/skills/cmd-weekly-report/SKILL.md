# /cmd-weekly-report [sync]

Vault root: this skill's folder resolved with `realpath`, three levels up (`<vault>/LLM/skills/<name>/`); run the commands below from there. Target `LLM/WEEKLY_REPORT.md`; source `LLM/DEV_STATUS.md` (history: `LLM/PROGRESS_ARCHIVE.md`, read only when needed).

- **REPORT STRUCTURE** (`WEEKLY_REPORT.md`, Markdown + one HTML status board, no inline HTML / colors elsewhere):
    1. `# Project Weekly Report`, then `> 週期：YYYY-MM-DD ~ YYYY-MM-DD (Week NN)` (Mon ~ Sun, ISO week).
    1a. `## 狀態總覽`: one **HTML board** (no mermaid; Obsidian renders it, same design as the Word board: 2pt ink frame, title row with the 週期, a stacked status bar, a summary line, one row per part, a legend). It is **generated by the script**: every `weekly_report.py` run rewrites the block from its own data, so the bar and the counts never go stale. Edit only the data: each part row is `<b data-part="N" ...>韌體</b>` followed by its items `<span data-st="Updated|New|On Hold|Finished" ...>■ short name</span>`. To add or move an item, change its `<span>` (or add one) and run the script (`python3 Tools/weekly_report/weekly_report.py`); it rebuilds the markup, sorts items New → Updated → On Hold → Finished, and recounts. Parts: one per project area, last `其他`. **Short name only** (no number, no %, no group prefix). Colours are the P6 status colours of the Word palette. The block has no blank lines (a blank line ends an HTML block in Markdown). An old mermaid board still parses (fallback) and is converted on the next run.
        - Keep it in sync with the blocks: same parts and labels.
    1b. `## 本週重點`: three bullets, one line each (`- **標題**：一句話`), the week's most important results; it is the first box of the right column in Word.
    2. `## 工作項目`: one `### N. <工作項目> (xx%) (Label)` block for **every** part the user has worked on or is working on. Never drop a block because it had no progress this week.
    3. Inside a block: **this week's updates first**, then a `---` line, then **history** (abstract of the most important past results). A block with no update this week has only the history part (no `---` line).
    4. Each bullet is one line: `- **短標題**：一句話重點`. Abstract only: the result and why it matters, no step-by-step, file lists or offsets. Max 4 bullets above `---`, max 4 below.
    5. Then `## 開發環境與版控`, `## 本週問題與待辦事項` (`### 問題`, `### 待辦事項`), `## 導入 LLM 協助開發與協同作業`.
- **NEW WEEK ROLL**: If today is after the `週期` end date, first update `週期` to the current week, then in every block move the old this-week bullets below `---` into history (merge with existing history, keep the 4 most important), remove the empty `---`, and drop `(Updated)`. Old items that fall out of history go to `PAST_REPORTS.md`.
- **/cmd-weekly-report**: Rebuild this week's part of `WEEKLY_REPORT.md` from `DEV_STATUS.md` following **REPORT STRUCTURE** (apply **NEW WEEK ROLL** first if needed).
- **/cmd-weekly-report sync**: Update `WEEKLY_REPORT.md` from chat context (and `DEV_STATUS.md` `Today`) following **REPORT STRUCTURE** (apply **NEW WEEK ROLL** first if needed). Add new progress above the `---` of the matching block; create a new block with `(New)` if the work part is new. Update `xx%`, labels, 問題 and 待辦事項.
- **PIN UPDATED BLOCKS**: Blocks labeled `(Updated)` or `(New)` MUST be moved to the top of `## 工作項目`; renumber the blocks.
- **STATUS LABELS** (only these four, no `(Ongoing)`):
    - `(Updated)`: existing block with new progress this week.
    - `(New)`: block added this week.
    - `(On Hold)`: no progress this week.
    - `(Finished)`: closed work (e.g. `開發環境與版控`).
- **Formatting**: Technical items include completion % (increments of 10) and status tag (e.g., `### 1. Item (70%) (Updated)`). **CRITICAL**: `WEEKLY_REPORT.md` MUST NOT use "100%" or "Completed" labels (max 90%).
- **Tone**: Traditional Chinese in the user's work-log style: read `LLM/TONE.md` first and follow its Profile, Edit pairs and Own samples (neutral written Taiwan workplace Chinese, verb first, summary level, technical terms in English, no Mainland wording).
